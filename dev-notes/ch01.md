### 关键产出

- `docs/ch01-spec.md` —— 设计定稿。含范围边界、三个验收点到接口的映射、目录结构、6 条关键决策、验证策略、已知风险。
- 已核实的 API 事实（不凭记忆，均经 Context7 + 本地实测）：`trim_messages` 完整签名与 `start_on='human'` 行为；`with_structured_output` 默认 `method='json_schema'`；`ChatOpenAI` 的 `base_url` / `api_key` 别名可用。

### 拒绝或纠偏

- **范围主动收敛**：上一轮我问范围时用户选的是「A 窄而深：售后闭环」，本轮用户把 ch01 砍到「纯对话，不做工具调用」。我按新范围重写规格，没有沿用旧设计里的工具链部分。
- **没有扩范围**：我自己上一轮建议过「A+ 售后闭环 + 商品问答 RAG」，这轮没往里塞。
- **PromptTemplate 的路线选择**：用户点名 `PromptTemplate`。chat 模型更常用的写法是 `ChatPromptTemplate.from_messages` + `MessagesPlaceholder`，但这里只需渲染一段 system 文本，用不上占位符机制。选定 `PromptTemplate` + 手工组装消息，理由写进了 spec 4.6，没有偷偷换。

### 翻车与返工

1. `gh auth login` 直连 github.com 超时（`wsarecv` 超时）。定位到本机 `127.0.0.1:7897` 有 Clash，走代理 `200`。已给仓库配 `http.https://github.com/.proxy`。
2. 用户回「登陆好了」，但 `~/.config/gh/hosts.yml` 和 `%APPDATA%\GitHub CLI\` 都不存在，`gh auth status` 仍报未登录——是浏览器登录了 github.com 网站，不是 CLI 授权。重新带代理跑 `gh auth login` 才成功。
3. Context7 MCP 在 `~/.workbuddy/mcp.json` 里配了，但本会话没注册成工具（工具列表无 `mcp__context7__*`）。改为直连 `https://mcp.context7.com/mcp`，写了 `tools/ctx7.mjs` 走 JSON-RPC。
4. Git Bash 把库 ID `/websites/langchain_oss_python_langchain` 当路径转成 `E:/Programs/...`，报 "Library not found"。加 `MSYS_NO_PATHCONV=1` 解决。
5. 抓 PyPI 版本时用 `tail -1` 取到的是字典序最大而非版本最大，得到 `fastapi 0.99.1` 这种假版本。改用 pip 实际解析，真实版本是 `fastapi 0.162.0`。
6. `tiktoken.get_encoding('cl100k_base')` 首次调用耗时 71 秒（联网下载 BPE 表），一度以为卡死。二次加载 0.3 秒。

**红-绿证据**：三组测试各自先跑出 `ModuleNotFoundError: No module named 'app.schemas' / 'app.service' / 'app.main'`，确认红灯后才写实现。最终 `39 passed in 2.02s`。

依赖实际版本：fastapi 0.162.0 / langchain 1.4.7 / langchain-core 1.7.3 / langchain-openai 1.7.3 / pydantic 2.14.2 / uvicorn 0.54.0。

### 拒绝或纠偏

- **没有引 `sse-starlette`**：环境里装了，但只有三种事件，用不上它的心跳与重连能力。手写 SSE 帧，少一个依赖。
- **没有为了测试方便给 `ChatService` 加 if 判断**：模型通过构造注入，测试用 FakeModel 顶替，业务代码里零测试分支。
- **`extract` 没有复用 `self.model` 的缓存**：`with_structured_output` 每次调用都新建 Runnable。看起来浪费，但 ChatOpenAI 的 `with_structured_output` 本身是轻量包装，提前缓存反而要给 `extra_body` 之类配置做失效管理，YAGNI。
- **按约定没有换技术栈**：`glm-4.7-flash` 的 `function_calling` 是否稳定要等真实调用才知道，先不预判、也不换成 `langchain-anthropic`。

### 翻车与返工

1. `tests/conftest.py` 起初把 `FakeModel` 当普通类导出，`test_api_stream.py` 里 `from tests.conftest import FakeModel` 会失败——`tests/` 没有 `__init__.py`，不是包。改成测试文件不导入、只靠 fixture 拿对象。
2. `SessionStore` 原来没有清空全部会话的入口，接口测试会互相污染。补了 `clear_all()`，在 client fixture 前后各清一次。
3. `Settings` 在测试里被实例化多次，`llm_api_key="test"` 靠 kwargs 覆盖；如果改用环境变量会污染其他用例，`construct` 方式更干净。
